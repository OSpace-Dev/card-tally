# 数据与接口说明

## 服务结构

浏览器通过同源 `/api` 请求访问 Express，Express 使用 Node.js 内置 `node:sqlite` 保存账本。公网环境由 Nginx 提供 `dist` 静态文件，并将 `/api/` 代理到 Docker 后端；开发环境由 Vite 代理 API。本机 `npm start` 仍支持后端同时提供静态文件。

SQLite 开启 WAL、外键约束及 5 秒 busy timeout。初始化建表可重复执行，不覆盖已有数据。当前 `PRAGMA user_version=1`，后续变更表结构时应补充版本迁移。

## 表结构

### cards：信用卡

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PRIMARY KEY | 自增 ID |
| bank | TEXT | 银行名称，1–30 字 |
| name | TEXT | 自定义卡片名称，1–30 字 |
| last4 | TEXT | 卡号末四位，保留前导零 |
| color | TEXT | 六位十六进制色值 |
| created_at | TEXT | 数据库创建时间 |

仅保存末四位，不保存完整卡号、有效期或安全码。允许同银行、多张卡，末四位不做全局唯一限制。

### transactions：记账记录

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PRIMARY KEY | 自增 ID |
| card_id | INTEGER | 外键，引用 cards.id，限制关联卡片删除 |
| type | TEXT | expense（消费）或 refund（退款） |
| amount_cents | INTEGER | 正整数分，方向由 type 决定 |
| date | TEXT | YYYY-MM-DD，自然日期，无时区偏移 |
| category | TEXT | 固定消费分类 |
| merchant | TEXT | 商户或内容，最多 80 字 |
| note | TEXT | 备注，最多 300 字 |
| created_at | TEXT | 数据库创建时间 |

日期和卡片 ID 有索引。退款独立记账，不要求关联原消费记录。

### budgets：每月预算

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| month | TEXT PRIMARY KEY | YYYY-MM，每月一条 |
| amount_cents | INTEGER | 正整数分 |

分类：餐饮美食、购物消费、交通出行、生活缴费、休闲娱乐、旅行住宿、教育学习、其他消费。当前不提供分类维护功能。

## API

所有接口要求请求头 `Authorization: Bearer <访问密钥>`。JSON 请求应带 `Content-Type: application/json`，请求体上限 32 KB。认证比较采用恒定时间比较；响应禁止缓存。返回金额除新增/编辑输入的 `amount` 外，均为**整数分**。

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | /api/session | 检查访问密钥，返回分类列表 |
| GET | /api/cards | 全部卡片 |
| POST | /api/cards | 新增卡片 |
| PUT | /api/cards/:id | 更新卡片 |
| DELETE | /api/cards/:id | 删除无关联记录的卡片 |
| GET | /api/transactions | 明细列表与总数 |
| POST | /api/transactions | 新增消费或退款 |
| PUT | /api/transactions/:id | 更新记录 |
| DELETE | /api/transactions/:id | 删除记录 |
| GET | /api/report?month=YYYY-MM | 月度统计 |
| GET | /api/reports/cards?year=YYYY | 全年逐卡逐月统计（全部卡片 × 12 个月） |
| PUT | /api/budget | 新增、更新、取消某月预算 |
| GET | /api/export | 导出 CSV |

卡片新增/更新请求：

```json
{"bank":"招商银行","name":"日常消费卡","last4":"0123","color":"#16665b"}
```

消费新增/更新请求：

```json
{"card_id":1,"type":"expense","amount":"120.35","date":"2026-03-15","category":"餐饮美食","merchant":"午餐","note":"周末聚餐"}
```

预算请求，`amount` 为空字符串、null 或字符串 `"0"` 时删除预算：

```json
{"month":"2026-03","amount":"8000.00"}
```

明细与导出的查询参数：

- `month`：必填，YYYY-MM。
- `card_id`、`type`、`category`：可选，精确筛选。
- `q`：可选，最多 80 字，按商户或备注的字面子串搜索。
- `page`：明细分页，默认 1。
- `page_size`：明细每页数量，默认 15，上限 100。

导出使用相同筛选条件，但忽略分页。CSV 含 UTF-8 BOM，文本双引号转义；公式前缀加单引号，避免商户或备注被表格软件解释为公式。

月度统计响应字段：

- `expense`、`refund`、`net`、`count`：月度总额与笔数。
- `budget`：本月预算，无预算为 0。
- `previousNet`：上月净支出。
- `byCard`：本月有记录的卡片，含消费/退款/净支出/笔数。
- `byCategory`：本月有记录的分类，含消费/退款/净支出。
- `daily`：有记账日期的净支出列表，无记录日不填充。
- `trends`：含当前月的近六个月消费、退款、净支出。

全年逐卡统计 `GET /api/reports/cards?year=2026`：

- `year` 必填，范围 1900–9998，仍要求访问密钥。
- 返回 `{ year, months, cards }`，`months` 为 1–12 月的 YYYY-MM 字符串。
- `cards` 包含全部现有卡片及 `expense`、`refund`、`net`、`count` 全年合计，每张卡另带 `months` 数组，逐月返回相同统计字段及 `month`。
- 无记录的卡片和月份填充 0；同一银行不同卡片按独立卡片 ID 汇总，退款按实际发生月份计入，不跨年抵扣原消费。
- 金额字段仍为整数分，不修改数据库结构。

错误响应格式为 `{"error":"可读错误信息"}`。状态码：400 参数错误，401 未认证，404 记录或接口不存在，409 关联数据阻止删除，500 服务内部异常。SQL 使用预编译语句与参数绑定。

## 使用边界

这是个人规模的单实例账本。后端 SQLite 为同步查询，月度统计会读取该月记录；适合个人日常记账，不定位为大型并发业务。访问密钥是共享权限，不区分只读/管理身份。密钥认证无独立登录令牌服务、无登录速率限制，不建议直接将服务端口暴露公网。
