# 测试说明

## 验证命令

```bash
npm test
npm run build
npm run test:e2e
```

浏览器测试需要 Playwright Chromium，先执行 `npx playwright install chromium`。Windows 已安装 Edge 时，可在 PowerShell 设置 `$env:PLAYWRIGHT_CHANNEL = "msedge"`，或在 Bash 使用 `PLAYWRIGHT_CHANNEL=msedge npm run test:e2e`。

## 后端覆盖

16 项自动化测试均使用系统临时目录内的独立 SQLite 数据库，测试结束后关闭连接并清理。

- 金额转换：分单位精度，拒绝零、负数、科学计数法和超过两位小数。
- 访问密钥最短 12 位，拒绝 11 位及空密钥，接受 12 位及更长密钥。
- API 密钥认证和响应禁止缓存。
- 卡片创建、尾号前导零、字段校验。
- 消费、当月退款、跨月退款。
- 自然月边界；卡片、分类、每日、趋势汇总一致。
- 空月份与负净支出。
- 全年逐卡逐月统计，覆盖 12 个月零值补齐、同银行多卡、跨月退款、跨年隔离、全年合计及认证。
- 不存在日期、无效卡片/分类、月份注入、分页校验。
- 明细搜索、筛选、分页。
- 按月预算设置、修改、清除与月份隔离。
- 关联记录阻止删卡，卡片编辑反映到报表。
- CSV 字符转义、公式前缀防护及筛选。
- 删除记录、无关联卡片及 404。
- 服务关闭后重新打开 SQLite，数据仍然存在。
- SQLite 外键和完整性检查。

## 浏览器覆盖

使用实际浏览器访问构建后的前端，测试服务器监听 3099 端口，使用临时数据库。

完整流程：

1. 电脑输入访问密钥，进入账本。
2. 电脑新增卡片，确认尾号显示。
3. 手机独立浏览器会话登录同一账本。
4. 手机新增 123.45 元消费，再记 23.45 元退款，确认净支出 100 元。
5. 手机进入明细，确认两条记录与商户显示。
6. 电脑刷新后显示同一净支出。
7. 电脑设置 1000 元预算，确认剩余 900 元。
8. 电脑搜索商户、筛选记录、触发 CSV 下载。
9. 在 375、768、1024、1440 像素宽度下逐一打开总览、明细、卡片页，检查无页面横向溢出。
10. 直接访问 `/cards`，验证浏览器前进后退切换页面；刷新 `/records` 后保持原路由及登录状态。
11. 手机刷新后账本数据保留；锁定后返回登录页。
12. 确认流程中无浏览器未捕获脚本异常。
13. 各卡月度统计全年 12 个月、消费/退款/净支出合计及点击月份跳转明细；四种视口均覆盖该路由。
14. 手机默认显示内置数字键盘，拒绝第三位小数，切换完整表单保留金额。

另有独立手机极简模式测试：375 × 667 视口下，仅通过数字键盘和卡片选择保存 0.01 元，确认零金额校验、默认日期/分类/类型、实际保存至所选卡片、下次沿用选卡，以及编辑时显示完整表单。保存按钮在该视口内可见。


路由页位于 `src/views/`，公共布局位于 `src/layouts/`，表单弹窗位于 `src/components/`。生产部署由 Nginx 的 `try_files` 处理子路由刷新；浏览器测试由独立测试服务器提供相同的前端入口回退。

## 性能回归

`tests/browser/performance.spec.ts` 在真实浏览器中检查：

- 已记住设备的总览首屏只请求 session、cards、report 三个 API，不获取消费明细。
- 首屏不会下载未打开的登录页、记账/卡片/预算弹窗、明细页和安装说明资源。
- 切换到消费明细或筛选时只请求明细，不重复请求总览。
- 各卡年度统计不重复请求，总览和明细接口不随之加载。
- 信用卡管理页不拉取无关报表，打开添加卡片时才下载对应表单。

npm run build
npm run analyze
```

## 手机表单与保存回归

`tests/browser/mobile.spec.ts` 新增两条移动端测试：

- 银行默认点选，选择器的输入保持只读，避免选择银行时同时调出文字键盘；手动输入银行是单独操作。检查名称、搜索、日期、分类选择器等可见文本输入实际字号至少 16px，不通过禁止浏览器缩放处理 iOS 自动放大。
- 在 375 × 667 视口下检查极简面板，银行卡按钮保持 44px 触控高度，保存和取消按钮至少 52px 且可直接看到；模拟提交和列表刷新分别延迟，确认入口持续禁用、表单内容不被重置，重复触发提交只发送一个写入请求，结束后可以正常记下一笔。

完整构建及 12 条浏览器测试已分别在 Edge 和 WebKit 上通过。模拟环境无法显示 iOS 的原生软键盘或完全复现系统自动缩放，相关触感与视觉效果仍需 iPhone 真机验收。

## iOS Web App 与登录持久化

`tests/browser/pwa.spec.ts` 新增 7 条浏览器测试，与原有 2 条业务流程、1 条性能回归及 2 条手机表单测试共 12 条。分别在 Edge（Chromium）和 Playwright WebKit 上验证：

- iOS 独立窗口 meta、manifest 的 standalone 模式、图标资源和 Safari 安装步骤。
- 默认记住设备，关闭页面重开可直接登录；取消勾选仅保留标签页会话。
- 从保存的站点存储创建新浏览器会话后可恢复登录。
- 锁定清除本地/会话密钥，其他标签页同步退出。
- 临时网络失败保留密钥，可重试连接；401 清除失效密钥。
- 浏览器拒绝写入存储时，当前页面仍可正常登录。
- 离线页面及图标可用，恢复网络可重新进入；Service Worker 缓存不含 API 数据。
- 模拟独立窗口时不再显示安装引导入口。

```

```

```

WebKit 的模拟视口和独立窗口标志不等同于 iPhone 真机，系统的“添加到主屏幕”、地址栏隐藏、状态栏与安全区视觉效果仍需在 iOS Safari 真机确认。未执行公网部署、真实跨设备网络或大数据量压力测试。

测试失败时 Playwright 会保存 trace 至 `test-results`，可用 `npx playwright show-trace <trace.zip路径>` 查看。
