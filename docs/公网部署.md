# 公网部署：Nginx 前端 + Docker 后端

前端构建为静态文件，直接放在现有 Nginx 上。后端使用 Docker Compose 运行一个 Node.js API 容器，SQLite 和访问密钥保存到持久化卷。无需额外安装 Node 服务或配置 systemd。

以下示例使用 Ubuntu 24.04、宿主机 Nginx、Docker Engine + Compose v2，以及域名 `ledger.example.com`，请替换为你的域名。

## 1. 结构

```text
浏览器 https://ledger.example.com
                 │
               Nginx
                 ├── /、/overview、/records、/cards → /var/www/card-ledger 静态文件
                 └── /api/* → 127.0.0.1:3001 → Docker API 容器
                                                   └── /data → card-ledger-data 卷
```

前端始终请求同域 `/api`，无需配置 CORS 或在浏览器中填写后端地址。生产容器只包含后端，不包含前端源码或 `dist`。容器内监听 `0.0.0.0:3001`，宿主机仅绑定 `127.0.0.1:3001`。

前置条件：

- 服务器已安装 Nginx、Docker Engine 和 Compose v2，`docker compose version` 可运行。
- 域名 A 记录指向服务器。只有 IPv6 正确配置后才添加 AAAA 记录。
- 云安全组开放 80/443，SSH 仅允许管理来源，**不要开放 3001/5173/3099**。
- 国内服务器按服务商要求处理域名备案。

当前应用是单人/家庭共享密钥账本，持有密钥者可操作全部数据。通过 HTTPS 使用，不将密钥放在网址里。

## 2. 本机构建前端并上传

本机需要 Node.js 24+：

```bash
npm ci
npm run build
```

将 `dist/` **内部的文件**上传到服务器 `/var/www/card-ledger/`，最终结构应为：

```text
/var/www/card-ledger/
  index.html
  assets/
```

可通过 SFTP、面板或 SCP 上传。Windows PowerShell 示例：

```powershell
scp -r dist 管理用户@服务器IP:/tmp/card-ledger-dist
```

服务器执行（首次部署）：

```bash
sudo install -d -m 0755 /var/www/card-ledger
sudo cp -a /tmp/card-ledger-dist/. /var/www/card-ledger/
sudo chown -R root:root /var/www/card-ledger
sudo find /var/www/card-ledger -type d -exec chmod 0755 {} +
sudo find /var/www/card-ledger -type f -exec chmod 0644 {} +
```

若临时目录已经存在，先换一个新的上传目录，避免 SCP 形成额外的 `dist` 嵌套层。

## 3. 上传后端部署文件

后端 Docker 构建需要以下内容：

```text
/opt/card-ledger/
  Dockerfile
  .dockerignore
  compose.yaml
  package.json
  package-lock.json
  server/
  deploy/
```

可直接上传项目源码，但不要上传本机 `node_modules/`、`data/`、`.env` 和测试临时文件。不要把整个源码目录配置为 Nginx 根目录。

服务器准备目录：

```bash
sudo mkdir -p /opt/card-ledger
sudo chown "$(id -un):$(id -gn)" /opt/card-ledger
```

在本机项目目录上传（目标目录准备好后执行）：

```powershell
scp Dockerfile .dockerignore compose.yaml package.json package-lock.json 管理用户@服务器IP:/opt/card-ledger/
scp -r server deploy 管理用户@服务器IP:/opt/card-ledger/
```

## 4. 启动 API 容器

服务器执行：

```bash
cd /opt/card-ledger
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 api
```

如果账户无 Docker 权限，在命令前加 `sudo`；Docker 组成员等同拥有主机管理权限，应只给可信管理账户授权。

配置默认包含：

- 非 root 用户 `node` 运行。
- 程序文件系统只读，仅 `/data` 持久化卷和临时目录可写。
- `restart: unless-stopped`，主机重启且 Docker 服务启动后会恢复运行。
- 健康检查和日志大小限制。
- 命名卷 `card-ledger-data`，保存 `ledger.sqlite` 和 `access-key.txt`。

第一次使用新卷时，Docker 会从镜像初始化 `/data` 的所属用户，无需在宿主机手动创建数据库文件。重建或删除容器不删除命名卷。

检查接口：

```bash
curl -i http://127.0.0.1:3001/api/session
```

返回 `401` 表示服务运行且要求认证。容器健康检查以该状态作为服务存活信号，不代表认证业务测试。

获取首次登录密钥，仅在自己的 SSH 终端查看：

```bash
docker compose exec -T api node -e 'process.stdout.write(require("node:fs").readFileSync("/data/access-key.txt", "utf8")+"\n")'
```

默认使用自动生成的随机密钥；不要额外设置 `ACCESS_KEY`，避免出现环境变量与文件两种来源。`docker compose down` 会保留数据，**`docker compose down -v` 会删除账本卷，不要用于日常更新**。

## 5. Nginx 配置

如果已有网站和 HTTPS 配置，将下面的核心内容合并进对应站点即可：

```nginx
root /var/www/card-ledger;
index index.html;

location /api/ {
    # 不加结尾 /，保留 /api 路径
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
}

location / {
    try_files $uri $uri/ /index.html;
}
```

`try_files` 是 Vue Router history 模式所需，确保刷新 `/records`、`/cards` 时仍返回前端入口。

完整模板另含 API 限流和静态资源缓存：

```bash
sudo cp /opt/card-ledger/deploy/card-ledger-limits.conf /etc/nginx/conf.d/card-ledger-limits.conf
sudo cp /opt/card-ledger/deploy/card-ledger.nginx.conf /etc/nginx/sites-available/card-ledger
sudo nano /etc/nginx/sites-available/card-ledger
```

改好 `server_name` 后首次启用：

```bash
sudo ln -s /etc/nginx/sites-available/card-ledger /etc/nginx/sites-enabled/card-ledger
sudo nginx -t
sudo systemctl reload nginx
```

已存在同名链接则跳过 `ln -s`。不要重复配置同一个域名。Nginx 是宿主机现有服务，不需要将其一起容器化。

限流模板假设 Nginx 直接接收客户端请求。使用 CDN/其他前置代理时，先按供应商配置可信来源和真实 IP，再启用按 IP 限流。

如果 Nginx 本身已在 Docker 中，`127.0.0.1` 指向的是 Nginx 容器本身：应将两个容器加入同一 Docker 网络，使用 `proxy_pass http://api:3001`，并将前端文件挂载到 Nginx 容器；本文默认宿主机 Nginx。

## 6. HTTPS

已有 HTTPS 可以跳过此节。未配置时：

```bash
sudo apt update
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d ledger.example.com --redirect
sudo certbot renew --dry-run
```

确认域名解析和 80 端口可访问后再申请，按提示填写邮箱。未完成 HTTPS 时，不在 HTTP 页面输入密钥。

开放主机防火墙时先允许实际 SSH 端口，再放行 80/443。例如标准 SSH 端口的 Ubuntu UFW：

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
```

网站入口为 **https://ledger.example.com**，手机和电脑输入同一个访问密钥，即连接同一账本。

## 7. 更新

前端更新：本机重新 `npm ci && npm run build`，上传 `dist` 内部文件到 Nginx 站点。建议先上传新 `assets`，最后替换 `index.html`；暂时保留旧的哈希资源文件，避免仍打开旧页面的浏览器加载失败。`index.html` 不长期缓存。

后端更新：先备份，再更新 `server/`、`Dockerfile`、包清单和锁文件，执行：

```bash
cd /opt/card-ledger
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 api
```

不需要在宿主机运行 npm，不需要 systemd 管理 Node。已有 HTTPS 配置无需覆盖。

数据库位于独立卷，构建镜像和更新程序不会覆盖数据库。回滚时恢复上一版本后端源码/锁文件并重新构建；未来若有数据库结构迁移，需同时确认旧版本兼容性，必要时恢复更新前备份。

## 8. 备份

推荐个人账本使用短暂停机备份。脚本会暂停 API、复制整个数据目录、恢复服务、检查数据库并压缩；备份期间前端页面仍可打开，但记账请求暂不可用。

服务器安装依赖并执行：

```bash
sudo apt install -y sqlite3
sudo bash /opt/card-ledger/deploy/backup.sh
```

默认从 `/opt/card-ledger/compose.yaml` 操作容器，备份到 `/var/backups/card-ledger/`，保留约 30 天。自定义路径可用 `LEDGER_PROJECT_DIR` 和 `LEDGER_BACKUP_DIR` 环境变量。

自动备份：

```bash
sudo crontab -e
```

添加每天 03:15 的任务：

```cron
15 3 * * * /usr/bin/bash /opt/card-ledger/deploy/backup.sh >> /var/log/card-ledger-backup.log 2>&1
```

备份包包含数据库和密钥，应加密后另存到服务器以外的私有存储。CSV 仅是明细导出，不是完整备份。不要在运行中仅复制 SQLite 主文件，最新记录可能在 WAL 文件中。

## 9. 恢复与本机账本迁移

先使用上一节备份当前服务器数据。将可信备份解压到服务器 `/tmp/card-ledger-restore/`，确保其中直接包含 `ledger.sqlite`、`access-key.txt`，不是再套一层目录。

恢复前检查：

```bash
sqlite3 /tmp/card-ledger-restore/ledger.sqlite 'PRAGMA integrity_check;'
```

返回 `ok` 后执行：

```bash
cd /opt/card-ledger
docker compose stop api
# 容器停止后，将旧卷完整复制留档，确保有回退数据
sudo mkdir -p /var/backups/card-ledger/pre-restore
docker compose cp api:/data/. /var/backups/card-ledger/pre-restore/

# 只清空明确的 /data 卷，随后复制恢复文件；这里会替换实际账本
# 使用 Docker 中的 node 用户，保证恢复后权限匹配
docker compose run --rm --no-deps --entrypoint node api -e 'const fs=require("node:fs"); for(const name of fs.readdirSync("/data")) fs.rmSync("/data/"+name,{recursive:true,force:true});'
docker compose cp /tmp/card-ledger-restore/. api:/data/
# docker cp 可能保留宿主机归属，统一修复为镜像 node 用户 UID/GID 1000
docker run --rm --user 0:0 -v card-ledger-data:/data node:24-bookworm-slim sh -c 'chown -R 1000:1000 /data && chmod 700 /data && find /data -type f -exec chmod 600 {} +'
docker compose start api
```

使用恢复后的密钥登录，核对卡片、消费、退款和预算。恢复前清空旧卷内容是为了避免混入旧 `-wal` / `-shm` 文件。

从 Windows 迁移时，先停止本机 Node 服务，复制整个本机 `data` 目录里的文件（包括存在的 `-wal` / `-shm`）到恢复临时目录，再按上述步骤恢复。迁移完成后，以公网服务为统一账本，不继续向旧本机数据库记账。

## 10. 轮换密钥

```bash
cd /opt/card-ledger
docker compose exec -T api node -e 'require("node:fs").writeFileSync("/data/access-key.txt", require("node:crypto").randomBytes(24).toString("base64url"), {mode:0o600})'
docker compose restart api
```

再次通过第 4 节命令查看新密钥，各设备重新登录。恢复历史备份可能恢复旧密钥，必要时再次轮换。

## 11. 故障排查与验收

| 现象 | 检查 |
| --- | --- |
| 502 | `docker compose ps`、`docker compose logs api`、本机 3001 端口 |
| 刷新 `/records` 显示 404 | Nginx 是否配置 `try_files ... /index.html` |
| API 返回 HTML | `/api/` 没有独立代理，被前端回退规则接管 |
| 容器返回首页 404 | 正常：容器只提供 API，首页由 Nginx 提供 |
| API 401 | 密钥不匹配，确认正在访问对应命名卷 |
| SQLite 无法写入 | 数据卷归属应为 node 的 1000:1000，检查磁盘空间 |
| 更新后账本为空 | 检查命名卷 `card-ledger-data`，是否改名或执行过 `down -v` |
| API 429 | 触发 Nginx 限流，检查前置代理真实 IP 配置 |

上线后验证：HTTPS 正常、未认证 API 为 401、容器健康、手机电脑记账一致、刷新子路由正常、重建容器后数据保留、备份恢复可用。

部署后请使用 `docker compose config`、容器健康状态和 `nginx -t` 检查配置，并实际验证 HTTPS 登录、记账、统计和备份恢复。
