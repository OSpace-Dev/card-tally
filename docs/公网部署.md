# 卡有数 · CardTally 部署指南

部署方式：**Nginx 托管前端 + Docker 运行后端 + `./data` 保存数据库**。前后端共用一个站点，浏览器通过同域 `/api` 请求后端。

以下以 Ubuntu、宿主机 Nginx、Docker Engine + Compose v2 为例。示例域名 `card-tally.example.com` 和服务器路径可按实际情况替换。

## 1. 数据放在哪里

```text
部署目录（例如 /opt/card-tally）/
  compose.yaml
  Dockerfile
  package.json
  package-lock.json
  server/
  deploy/
  data/                    ← 宿主机实际文件，更新容器后保留
    card-tally.sqlite
    access-key.txt
    card-tally.sqlite-wal      ← 运行时可能存在
    card-tally.sqlite-shm      ← 运行时可能存在
```

Compose 使用目录绑定 `./data → 容器 /data`，不创建命名卷，Dockerfile 也不声明匿名卷。`./data` 相对于 **compose.yaml 所在目录**，不是浏览器或 Nginx 所在目录。只要保留该目录，停止、删除、重建容器都不会删除账本。

请把数据目录放在服务器持久化磁盘上，不要上传到 Git，也不要放进 Nginx 网站目录。

## 2. 127.0.0.1 和 0.0.0.0 的区别

```text
手机 / 电脑 → 服务器IP或域名:80/443 → Nginx
                                     ├── 前端静态文件
                                     └── /api → 宿主机127.0.0.1:3001 → API容器
                                                                          └── ./data
```

有三处监听/代理地址，含义不同：

| 位置 | 默认配置 | 作用 |
| --- | --- | --- |
| API 容器内 `HOST` | `0.0.0.0` | 容器接收 Docker 转发的请求，保持不变 |
| Docker 宿主机端口 | `127.0.0.1:3001:3001` | 只有同机程序可以直接访问后端端口 |
| 宿主机 Nginx | `listen 80` / HTTPS 443 | 向局域网和公网提供网站，API 由 Nginx 转发 |

**Nginx 和 Docker 在同一台主机时，保留 Docker 的 127.0.0.1，局域网仍可以通过 `http://服务器局域网IP` 使用全部功能。** 手机访问 Nginx 的 80/443 端口，无需直连 3001。

只有以下情况才需要调整 Docker 端口绑定：

- Nginx 在另一台机器，需要跨主机访问 API。
- 需要从局域网直接调试 API 的 3001 端口。

在 compose.yaml 同目录复制 `.env.example` 为 `.env`，修改：

```dotenv
API_BIND_ADDRESS=0.0.0.0
API_PORT=3001
```

也可以绑定明确的服务器局域网 IP，减少不必要的监听范围。然后执行 `docker compose up -d`。跨主机 Nginx 的 `proxy_pass` 应填写 **API 服务器的实际局域网 IP**，例如 `http://192.168.1.20:3001`；`0.0.0.0` 只表示监听所有 IPv4 网卡，不能作为浏览器或代理的目标地址。防火墙只允许 Nginx 主机或可信局域网访问后端端口。

如果 Nginx 本身运行在容器中，`127.0.0.1` 是该 Nginx 容器：让两个容器加入同一个 Docker 网络，代理地址改为 `http://api:3001`，不必为此将 API 暴露到公网。本文配置默认宿主机 Nginx。

## 3. 准备文件与首次启动

服务器先准备部署目录，再上传下列文件：

```text
Dockerfile、.dockerignore、compose.yaml、.env.example
package.json、package-lock.json、server/、deploy/
```

例如本机 PowerShell 上传：

```powershell
scp Dockerfile .dockerignore compose.yaml .env.example package.json package-lock.json 管理用户@服务器IP:/opt/card-tally/
scp -r server deploy 管理用户@服务器IP:/opt/card-tally/
```

目标目录需提前创建，并允许管理账户上传。不要上传本机 `node_modules/`、账本 `data/`、密钥或 `.env`；备份恢复参照第 8 节。

首次运行前，在服务器创建数据目录并赋予容器用户权限：

```bash
cd /opt/card-tally
sudo install -d -o 1000 -g 1000 -m 0700 ./data
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 api
```

镜像使用 `node` 用户，UID/GID 为 1000:1000。目录绑定不会像命名卷一样自动继承镜像内权限，因此必须初始化目录。配置设置了 `create_host_path: false`：忘记创建 `./data` 时直接报错，避免 Docker 自动创建 root 所属目录后导致 SQLite 无法写入。已有数据时先备份，不要覆盖文件；恢复后还需检查文件所属用户。

账户无 Docker 权限时在 Docker 命令前加 `sudo`。Docker 组成员具有主机管理权限，只授予可信管理账户。

检查本机 API：

```bash
curl -i http://127.0.0.1:3001/api/session
```

未携带密钥返回 `401` 为正常。若自定义 API_PORT，需要使用实际端口。健康检查也以未认证 401 判断服务存活，不替代实际业务验证。

首次密钥直接保存在宿主机文件，可通过 SSH 查看：

```bash
sudo cat ./data/access-key.txt
```

默认使用随机生成的文件密钥，无需设置 `ACCESS_KEY`；手动修改 `./data/access-key.txt` 时至少保留 12 个字符（含 12 个），修改后执行 `docker compose restart api` 才会生效。只在 HTTPS 登录页输入密钥，不要把它放入 URL、截图或公开工单。应用是个人/家庭共享账本，持有密钥者可修改全部数据，不具备独立用户权限。

## 4. 前端构建

本机 Node.js 24+ 执行：

```bash
npm ci
npm run build
```

将 `dist/` **内部文件**上传到 Nginx 网站目录，例如：

```text
/var/www/card-tally/
  index.html
  assets/
```

可使用面板、SFTP 或 SCP，确保 Nginx 用户能够读取静态文件。不要将整个源码目录或 `data` 放入网站目录。仅部署后端时，容器首页返回 404 为正常，容器只提供 API。

## 5. 前后端 Nginx 完整配置

仓库提供一份同时包含前端静态文件和后端代理的配置：

- [card-tally.nginx.conf](../deploy/card-tally.nginx.conf)：网站配置，前端、路由回退、缓存和 `/api/` 代理。
- [card-tally-limits.conf](../deploy/card-tally-limits.conf)：放在 Nginx `http` 上下文内的 API 限流定义。

如果使用模板，复制这两个文件并修改域名和网站根目录：

```bash
sudo cp /opt/card-tally/deploy/card-tally-limits.conf /etc/nginx/conf.d/card-tally-limits.conf
sudo cp /opt/card-tally/deploy/card-tally.nginx.conf /etc/nginx/sites-available/card-tally
sudo nano /etc/nginx/sites-available/card-tally
sudo ln -s /etc/nginx/sites-available/card-tally /etc/nginx/sites-enabled/card-tally
sudo nginx -t
sudo systemctl reload nginx
```

已有符号链接时跳过 `ln -s`，已有同域名站点时合并配置，避免重复启用。使用面板时将网站部分放到站点的 server 块，限流定义放在全局 http 块。

下面是可独立使用的前后端合并配置（不依赖额外限流文件）。与模板二选一，不要重复配置同一域名：

```nginx
server {
    listen 80;
    listen [::]:80;
    # 公网填域名；局域网可填服务器IP，例如192.168.1.20
    server_name card-tally.example.com;
    root /var/www/card-tally;
    index index.html;
    client_max_body_size 32k;

    # 后端：保留 /api 路径，因此 proxy_pass 后不要加结尾斜杠
    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 5s;
        proxy_read_timeout 60s;
        proxy_cache off;
    }

    # 前端构建后的哈希资源
    location /assets/ {
        try_files $uri =404;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
    location = /index.html {
        add_header Cache-Control "no-cache";
    }

    # 前端页面：支持直接访问和刷新子路由
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

这一个站点就包含了前端与后端配置，无需创建两个域名或让浏览器跨域。支持 `/overview`、`/card-statistics`、`/records`、`/cards` 等 Vue 路由。

局域网使用时将 `server_name` 改为服务器实际局域网 IP，手机访问 `http://服务器IP`，**不是 `http://服务器IP:3001`**。如服务器有多个站点，必须确认请求匹配本网站的 server 块。

模板的限流按 Nginx 接收到的客户端 IP 计算。如果再加 CDN/前置代理，应先配置可信来源网段和真实 IP，避免全部用户被当作一个来源。

## 6. 公网 HTTPS 和端口

域名 A 记录指向服务器；仅在 IPv6 正常时设置 AAAA 记录。中国大陆服务器按服务商要求处理备案。

已有 HTTPS 配置可跳过证书申请。未配置时：

```bash
sudo apt update
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d card-tally.example.com --redirect
sudo certbot renew --dry-run
```

80 端口需能从公网访问用于验证证书。申请后检查 HTTP 跳转 HTTPS、443 返回正常、证书自动续期已设置。未启用 HTTPS 前，不在公网 HTTP 页面输入密钥。

Nginx 和 Docker 同机时，安全组/主机防火墙只需开放网站 80/443 和受控 SSH，**不开放 3001**。若启用 UFW，先放行实际 SSH 端口再启用，避免失去连接。

## 7. 更新与备份

前端更新：重新构建并上传 `dist` 内容，建议先上传新 `assets`，最后替换 `index.html`，暂时保留旧哈希资源供已打开页面使用。

后端更新：先备份，再更新源码与 Docker 构建文件，执行：

```bash
cd /opt/card-tally
docker compose up -d --build
docker compose ps
```

保持同一部署目录下的 `./data`，不要用空文件夹覆盖。更新后的 API 会继续读取原数据库。如果移动整个部署目录，应一起移动 `data` 并确认新路径挂载正确。

备份脚本会短暂停止 API，复制宿主机 `./data`，恢复服务，再检查与压缩快照：

```bash
sudo apt install -y sqlite3
sudo bash /opt/card-tally/deploy/backup.sh
```

默认根据脚本位置找到部署目录，备份保存在 `/var/backups/card-tally`，约保留 30 天。可用 `LEDGER_PROJECT_DIR`、`LEDGER_BACKUP_DIR` 覆盖路径。root 定时任务示例：

```cron
15 3 * * * /usr/bin/bash /opt/card-tally/deploy/backup.sh >> /var/log/card-tally-backup.log 2>&1
```

备份包含数据库与访问密钥，加密后另存到服务器外的私有存储。CSV 不是完整备份；运行中不能仅复制 SQLite 主文件，最新数据可能在 WAL 文件里。

## 8. 备份恢复

先备份服务器当前状态，再将可信备份解压到全新临时目录，例如 `/tmp/card-tally-restore`。该目录应直接包含 `card-tally.sqlite`、`access-key.txt` 及可能存在的 WAL/SHM 文件，而不是再套一层 `data`。

SQLite 完整性检查可能需要读写临时目录；用有权限的账户执行：

```bash
sudo sqlite3 /tmp/card-tally-restore/card-tally.sqlite 'PRAGMA integrity_check;'
```

返回 `ok` 后停止服务，保留原目录，创建干净目录后恢复：

```bash
cd /opt/card-tally
docker compose stop api
sudo mkdir -p /var/backups/card-tally
# 把当前数据目录完整留档，避免新旧 WAL/SHM 混用
sudo mv ./data "/var/backups/card-tally/pre-restore-$(date -u +%Y%m%dT%H%M%S)"
sudo install -d -o 1000 -g 1000 -m 0700 ./data
sudo cp -a /tmp/card-tally-restore/. ./data/
sudo chown -R 1000:1000 ./data
sudo find ./data -type d -exec chmod 0700 {} +
sudo find ./data -type f -exec chmod 0600 {} +
# 重新创建容器，确保绑定新的 data 目录；不能只 start 原容器
docker compose up -d --force-recreate api
```

若还没有 `./data`，跳过 `mv`。复制来源必须是停止服务后取得的完整目录，或本项目备份脚本生成的快照。使用恢复后的密钥登录，确认数据正确后再清理旧目录。

## 9. 密钥轮换

服务运行时在容器内生成新密钥，实际会写入宿主机 `./data/access-key.txt`：

```bash
cd /opt/card-tally
docker compose exec -T api node -e 'require("node:fs").writeFileSync("/data/access-key.txt", require("node:crypto").randomBytes(24).toString("base64url"), {mode:0o600})'
docker compose restart api
sudo cat ./data/access-key.txt
```

各设备使用新密钥登录。恢复历史备份可能恢复旧密钥，必要时再次轮换。

## 10. 排查与验收

| 现象 | 检查 |
| --- | --- |
| 启动提示找不到绑定目录 | 在 compose.yaml 同目录创建 `data` |
| SQLite 无法写入 | `data` 和文件应属于 1000:1000，检查磁盘空间 |
| Nginx 502 | `docker compose ps`、日志及 Nginx 能否访问目标 API 地址 |
| 局域网网站打不开 | Nginx 是否监听 80/443、防火墙是否允许、server_name 是否匹配 |
| 跨机器 Nginx 连不上 API | Docker 是否绑定局域网地址或 0.0.0.0，代理目标是否是 API 主机实际 IP |
| 刷新子路由 404 | Nginx 的 `try_files ... /index.html` |
| API 返回 HTML | `/api/` 没有独立代理，被前端路由回退接管 |
| API 401 | 密钥不匹配，核对当前 `./data/access-key.txt` |
| 移动目录后数据为空 | 检查 compose.yaml 同目录下是否仍有原 `data` |

上线验收：`docker compose config --quiet`、容器健康、`nginx -t`、HTTPS 登录、手机电脑共用数据、刷新子路由、重建容器后数据保留、备份与恢复可用。模板需在实际服务器验证后使用。
